## Riscos residuais relevantes

1. **ALTO se mal configurado:** publicar Apps Script `execute as me` com acesso anônimo amplia a superfície de ataque. A autenticação real é o segredo compartilhado. Comprometimento do segredo possibilita forjar e-mails e acessar qualquer perfil no backend; nunca tratar segredo como identificação de usuário ou publicar em frontend/Git/Issue. Antes do deploy obter aceite do risco, segredos fortes/rotação/monitoramento e avaliar gateway alternativo se inadequado.
2. **ALTO se má política:** colocar todo o hostname atrás do Cloudflare Access pode bloquear a agenda pública/offline, enquanto deixar rotas privadas desprotegidas depende da validação JWT no Worker. Testar as duas condições e escolher aplicações/paths corretos.
3. **MÉDIO:** eventuais mudanças da programação oficial não são sincronizadas automaticamente; conservar IDs e não sobrescrever preferências. Registrar divergências editoriais (Eduarda Jorge/Davidovic, Diogo Dias/Porto Dias) sem inferir equivalência.
4. **MÉDIO:** Google Apps Script e Workers Free têm quotas/limites. Verificar latência de verificação JWT, disponibilidade e rate limits em conta real antes de liberar.
5. **MÉDIO:** verificação local de redirect Google e de tratamento de apóstrofos em Sheets foi feita com mocks; comportamento exato de redirecionamento/planilha real pode diferir. Falha do contrato real é gate de bloqueio, nunca justificar relaxar domínio ou encaminhar segredo.
6. **EVIDÊNCIA ATUALIZADA:** bloqueio DNS superado para testes por transporte local compactado sem acesso a serviços externos; hash Git SHA-1 do `public/schedule.json` original confere com blob da branch (`9ab9fb499255d52d03a57d0130af8d25d6f61b6e`). `npm run schedule:check` e exportador CSV passaram no Node 22 sobre o conteúdo integral original. Continua sem teste com Access/Sheets reais.

## Reauditoria de login/Access - 2026-10-09
- Um único Access Application self-hosted deve cobrir `/auth/login`, `/api/me` e `/api/preferences` com **um AUD**. Shell/agenda pública são excluídos. `wrangler.jsonc` executa Worker primeiro apenas para `/api/*` e `/auth/login`. O Worker verifica JWT mesmo com a borda protegida. Em Access incompatível com múltiplos destinos na mesma aplicação, **bloquear publicação** e solicitar decisão de migração para prefixo privado único. Ver `docs/M3_ACCESS_LOGIN.md`.
- Frontend tem botão Entrar com navegação de página inteira; mensagens distinguem 401/403, respostas 302/303/HTML, rede, ausência de autorização, expiração durante gravação. Em qualquer falha auth, valores privados em memória são descartados e nenhuma escrita é considerada confirmada. O parâmetro `/?access=denied` comunica estado visual, não autoriza.
- **PASS** no Node 22.16.0: `npm test` **36/36**, `npm run check`; smoke Chromium **35/35** com respostas Access simuladas, incluindo viewport móvel. A navegação para hostname sintético foi bloqueada pelo ambiente; o teste de CTA verificou a chamada e o destino com mock, não um login Cloudflare real.
- **PASS arquivo integral original:** 38.921 bytes com Git blob `9ab9fb499255d52d03a57d0130af8d25d6f61b6e` verificado localmente; `npm run schedule:check` 32 sessões, 16+16, 110 participações, 21 sobreposições; CSV pelo script original, **33 registros lógicos** e 10 colunas, com `npm run --silent schedule:csv > sessions.csv`.
- Risco residual sem alteração: políticas reais Cloudflare, múltiplos destinos, tela de login e logout/cookies, Apps Script/Google Sheets, PWA HTTPS/offline e gatilhos externos de deploy não foram integrados ou validados em produção.
